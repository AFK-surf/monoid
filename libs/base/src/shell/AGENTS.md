# The shell's binding (for agents)

Part of the base (`libs/base/AGENTS.md`).

- The Rust shell's binding (`client/shell`, via its C interface) for a program on `@effect`: `shell.mbt` the surface over `shell_native.mbt` (with `shell.c`), `shell_js.mbt` (with `client/iroh-wasm` and browser APIs) and `Shell::stood_in` for tests. Natively, a process whose host started the shell shares it (`bsh_attach`, `Shell::attached`): this side's call ids start past 2^40, the host hands their answers to `bsh_deliver`. A program whose own loop runs its thread (a window's) never calls `run`: it gives `bsh_on_wake` what wakes that loop when an answer is queued (on the shell's thread, at once if answers wait), and each round calls `Shell::turn`, which runs until nothing is ready, never waits, and says when its next timer is due. On js iroh is loaded from an address (`Shell::start`) or given (`Shell::start_with`, `IrohJs`); a worker has no localStorage, so `storage.*` fails there. A page keeps keys past localStorage's few MB in IndexedDB (`idb.*`, head of `shell_js.mbt`; an own map where there is none, Node); no other shell has those ops. A page's HTTP (`fetch`, `stream.open`, `stream.read`, `stream.close`, `fetch.cancel`) is its `fetch` with the Rust shell's JSON and bytes; no `entry`; a body read to its end frees its handle. A tab's claim (`claim_tab`, `tab.mbt`) keeps a core in one browser tab: a Web Lock of its name, taken over on a BroadcastChannel (`TabClaim::take_over`: the holder is told `Yielded` before it lets go); natively, or without either, `Held` at once. What a tab does on yielding is its program's.
